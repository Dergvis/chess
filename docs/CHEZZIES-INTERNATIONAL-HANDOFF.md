## 2. Hosting, build, and domain

The existing **Vercel** project is `cheezzies/chezzies-international`, connected to `Dergvis/chess`. `vercel.json` runs `npm ci` and `npm run build`, publishes `dist`, and deploys the Vercel serverless function under `api/`. Vite (`vite.config.mjs`) builds separate HTML entries for the homepage, six topic pages, parents, `/play/`, and 404. Node 22.12+ is required for the frontend build. No always-on self-managed production server is required by the current architecture.

`chezzies.app` is the Production canonical host; `www.chezzies.app` redirects to it. Vercel's Production environment/build serves the public site; branch builds are Vercel Preview. The `international-site` branch is the implementation branch although GitHub `main` remains old. Production releases have been made by building/redeploying a reviewed Preview commit **as Production in Vercel**, not by pointing the domain at a Preview build. This matters because `scripts/generate-site.mjs` sets Preview HTML to `noindex,nofollow` and Preview `robots.txt` to `Disallow: /`. Promoting a Preview artifact without a Production rebuild would risk publishing its noindex output. On 23 October 2026, commit `c5ab520` was rebuilt in Vercel Production as deployment `2WfzK9Cct4o6oKfnZVe9Ne2zPsLo`; the live homepage was checked afterward. Verify Vercel's current deployment before any later release.

The route configuration in `vercel.json` normalizes trailing slashes; rewrites only known internal `/play/.../` routes to the game HTML and `/api/.../` to `api/backend.mjs`. Legacy payment routes redirect to `/play/`. Internal game routes such as login/account/home have `X-Robots-Tag: noindex, follow`; they still load on refresh. The 404 page is separate. ## 4. Accounts, session, saves, and recovery

Visitors can play as guests. Browser-local progress uses `localStorage`. Creating an **international email/password account** enables cross-device saves. There is no active Google OAuth flow in the deployed international API, even if some shared types retain a `google` provider option. No Russian account or progress was imported. Preview and Production use separate Neon database branches per `docs/DEPLOYMENT.md`; a Preview account is not automatically present on `chezzies.app`.

Frontend auth calls are in `src/shared/lib/authApi.ts`; world sync is in `src/world/storage.ts` and `src/world/accountStorage.ts`; other player XP/match progress sync is in `src/shared/lib/playerProgressApi.ts`. The Vercel function `api/backend.mjs` allowlists HTTP methods/routes, checks request origins, and uses `DATABASE_URL` to call `api/neon-account.mjs`. When Neon is configured, the archival HTTPS bridge fallback is not used.

**Neon Postgres** persists `international_users`, `international_sessions`, `international_world_saves`, `international_player_progress`, `international_reset_tokens`, `international_auth_attempts`, `international_support_requests`, and `international_support_replies`. The function creates missing tables/indexes on first use. Passwords are salted and hashed with Node `scrypt`. Session and reset tokens are random; only SHA-256 hashes are stored in Neon. Session cookies are HttpOnly, Secure on HTTPS, SameSite=Lax, and last 30 days. Login/registration/reset are rate-limited. World saves are JSONB tied to user ID; a stale `updatedAt` write receives 409. Player progress is separate JSONB. Guest-to-account import is explicit; local account storage is namespaced, and account switching avoids another user's cached hero/progress.

Password recovery uses **Resend**, with the verified `chezzies.app` sending domain and `RESET_EMAIL_FROM=CHEZZIES <accounts@chezzies.app>`. Production reset links target `/play/reset-password/?token=...`, expire after one hour, are single-use, and invalidate existing sessions when the password changes. Secrets `DATABASE_URL` and `RESEND_API_KEY` live only in Vercel environment settings, never in browser code or Git. The owner previously completed a real reset/sign-in on Preview and confirmed hero/progress restoration on Production from another session. Do not repeat those tests using the owner's credentials.

## 5. Help chat and Telegram

The in-game Help panel is `src/features/support/SupportChat.tsx`; API calls are `src/shared/lib/supportApi.ts`. A question goes to `/api/support/messages`, is rate-limited (five per account/IP per 15 minutes), sent by a bot to the owner's private Telegram group, and stored in Neon with a ticket and Telegram message ID. The customer's email is not included in the Telegram message. Production registers a Telegram webhook when a new question is submitted. A team member must use Telegram's **Reply** function on the bot's ticket message; `api/neon-account.mjs` validates the webhook secret and configured group ID, then stores the reply under the ticket. The Help panel polls `/api/support/my` every 30 seconds while open and displays messages chronologically. Signed-in users can see their tickets across devices; guests use an HttpOnly browser cookie. Old tickets sent before message-ID linking may not receive matched replies. `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` are server-side Vercel settings.

## 6. Analytics, privacy, and search

`src/analytics.ts` injects **Vercel Web Analytics** only on the production host and strips query strings/fragments from page URLs. It records anonymous allowlisted site/game events and broad traffic-source categories. Its `/api/site-events` call currently gets a `204` from the backend: this endpoint is **not a separate persistent event warehouse**. The bounded diagnostic event buffer is in browser `sessionStorage`.

**Google Analytics 4** measurement ID is `G-NCWBHEH877` in `src/googleAnalytics.ts`. Its script loads only on the production host after optional visitor consent, not on Preview. Visitors can decline and change the choice via Privacy settings. The implementation groups all game routes to `/play/` and strips sensitive URL parameters/referrers; it does not intentionally transmit email, names, passwords, saved games, or full referrer URLs. GA4 and Vercel Analytics measure visits/actions, not Google indexing. Search Console is the place to check indexed pages, crawl errors, sitemap status, queries, and impressions.

Marketing HTML has unique titles/descriptions/H1, canonical URLs, Open Graph/Twitter metadata, locally rendered content, internal links, `Organization`, `WebSite`, `SoftwareApplication`, and topic-page `BreadcrumbList` JSON-LD. `robots.txt` excludes API and account/login URLs; the sitemap lists only eight public pages. There are no invented review/rating claims or special `GEO` schema. English copy and crawlable factual content make the product understandable to search/AI systems; neither Google indexing nor AI citations/traffic are guaranteed. The optional `scripts/indexnow.mjs` requires an `INDEXNOW_KEY` and explicit production-published confirmation; it is not a Google submission mechanism. Historical documentation says IndexNow had not been run.
